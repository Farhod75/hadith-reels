## Do not read that as a pass

**The harness was not constant across the four cases.** The TJ prompt mentioned
the plural-respectful verb convention. The UZ prompt did not. 004 found
`singular_verb_for_prophet`; 003 missed it. That difference is in my prompts,
not in the model or the case. Any cross-case comparison of that finding is
invalid, and it is one of the two misses that failed 003.

**The harness also under-equips relative to production.** It supplied THREE
defect shapes. The real agent reads the full recurring-defect table in
`reel-creation-pipeline.md`. So this measures "can a careful reader with three
hints find these", which is narrower than the question the corpus exists to
answer.

A correct run holds the prompt identical across cases except for the case text
and the matn, and supplies the same defect table the agent gets. This run did
neither. **The agent's v1 status remains unestablished.**

## The 003 misses

`meaning_drift_against_corrected_column` in H was not overlooked — it was
examined and declined: "standard scholarly gloss (contentment), explicitly
framed as explanation, so it isn't narrowing the matn." The framing is correct
and the conclusion is wrong: H states the narrowed reading AS the hadith's
meaning, which is the drift, labelled or not.

Same shape as the 2026-10-09 run's 002 miss, and as the one I made this week
defending a gloss inside an attribution twice before the linter settled it. A
confident exclusion costs more than a silent miss, because it looks like
diligence.

## Two corpus defects the run exposed

Both "false positives" flagged the same real thing: **non-matn wording inside
an attributed frame** — «Асл» inserted in 003, «ҳақиқӣ» in 004, «балки»
dropped in both, inside guillemets or a said-frame.

The must_not_flag entries scoped themselves to the qanaah-drift axis in their
NOTES but covered whole sentences in their LOCI, so they would have scored a
correct finding as a false positive — which under v1 fails the run outright.

Both narrowed, and the finding is now credited as
`optional/non_verbatim_inside_attribution`. It is not hypothetical: the same
defect shipped for real on R121 this week, where the Tajik S block
re-translated the hadith while its own C block quoted the row correctly.
